

## Add Claude Single-Prompt Engine

### Overview
Add "Claude (Single Prompt)" as a new execution engine option for grants. When selected, reports are generated by a single backend function call to the Anthropic Claude API with the user's prompt template (pre-populated with the provided GPT instructions), enriched with the researcher's inputs and grant guidelines.

### Prerequisites
- An `ANTHROPIC_API_KEY` secret needs to be added (you'll be prompted for this during implementation)

### Database Changes

**Migration: Add `claude_prompt_template` to `grant_versions`**
- `claude_prompt_template TEXT` (nullable) -- stores the editable Claude prompt per grant version
- Pre-populated with the provided prompt via a data update after column creation

### New Backend Function

**`supabase/functions/run-claude-report/index.ts`**
- Called by `generate-report` when `execution_engine === 'claude'`
- Loads application inputs: summary, public article URL, TRL, IP status
- Loads grant context: guidelines raw text, rubric, grant name
- Loads the `claude_prompt_template` from the grant version
- Interpolates inputs into the prompt template using shortcodes (e.g., `{{summary}}`, `{{articleContent}}`, `{{grantGuidelines}}`)
- Calls Anthropic Claude API (claude-sonnet-4-20250514) with the assembled prompt
- Creates a single `report_run_step` record for progress tracking
- Saves the HTML output to the `reports` table (same contract as the multi-step pipeline)
- Updates run status to completed, application status to completed
- Handles failure: marks run as failed with halt_reason

### Backend Modifications

**`supabase/functions/generate-report/index.ts`**
- After creating report run, check execution engine:
  - `claude`: set `total_steps: 1`, dispatch to `run-claude-report`
  - `cloud_run`/`edge`: existing flow via `enqueue-report`
- Skip prompt bundle validation for Claude engine

**`supabase/functions/api-generate-report/index.ts`**
- Support optional `engine: "claude"` override in API request body

**`supabase/config.toml`**
- Register `run-claude-report` function with `verify_jwt = false`

### Frontend Changes

**`src/components/admin/EngineSettingsCard.tsx`**
- Add "Claude (Single Prompt)" as a third option in the engine dropdown
- Always visible (not gated by `edgeAllowed`)
- Description: "Generates complete report in one AI call using Claude"

**`src/pages/admin/GrantEdit.tsx`**
- Add state for `claudePromptTemplate`
- Load/save from `grant_versions.claude_prompt_template`
- In the **Pipeline tab**: when engine is `claude`, show a large editable textarea for the Claude prompt template instead of the multi-step pipeline editor
- Include a "Reset to Default" button to restore the original prompt
- Show guidelines uploader alongside the prompt editor (guidelines are interpolated into the prompt at runtime)

### Claude Prompt Design
The stored template will contain the full prompt the user provided, with interpolation shortcodes added:
- `{{summary}}` -- researcher's 100-word summary
- `{{articleContent}}` -- public article URL content (if provided)
- `{{trl}}` -- Technology Readiness Level
- `{{ipStatus}}` -- IP status
- `{{grantGuidelines}}` -- raw text from uploaded guidelines PDF
- `{{grantRubricFormatted}}` -- formatted rubric criteria
- `{{grantName}}` -- name of the grant

The edge function will replace these shortcodes before sending to Claude.

### Report Saving
The `run-claude-report` function inserts into `reports` using the same structure as the existing worker-proxy save logic:
- `content_json.report_html` for the HTML viewer
- `inputs_snapshot_json` for reproducibility
- Updates application status to `completed`
- Sends completion email via `send-report-email`

### UI Flow for Admin
1. Go to Grant Edit > Details tab > set engine to "Claude (Single Prompt)"
2. Go to Guidelines tab > upload grant guidelines PDF (existing flow)
3. Go to Pipeline tab > see and edit the Claude prompt template (pre-populated)
4. Publish version

### UI Flow for Researcher
- Identical experience: select grant, fill inputs, run report
- Progress shows 1 step instead of 13+
- Report viewer is the same HTML viewer

### Risks
- **Edge function timeout**: Claude responses for full reports may approach the 60s limit. Mitigation: use claude-sonnet (fast) and set appropriate max_tokens. If timeouts occur, can migrate to a background approach later.
- **Single-prompt quality**: Won't match multi-step research depth with web searching. This is intentional as a faster, simpler alternative.
